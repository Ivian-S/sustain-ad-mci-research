# EXPERIMENT_PLAN — 正式实验执行方案

版本：1.0（实验启动方案，2026-11-20）。研究范围来自导师同意的 2026-11-10 开题报告。以下工程步骤与验收条件是执行建议；未指定的数值阈值均待核查或确认，不能当作已批准参数或已完成结果。

## 1. 研究设计

以 ADNI 临床 CU、MCI 为主要研究对象。选择符合条件的较早 T1 检查作为基线，必要时痴呆阶段可用于辅助训练或敏感性分析，主要解释仍针对 CU/MCI。不得将临床分组直接称为生物学确诊 AD。

| 模型 | 区域形态 | 个体 MSN | 基线认知 | 用途 |
|---|---|---|---|---|
| M1 | 是 | 否 | 否 | 形态学基线 |
| M2 | 是 | 是 | 否 | MSN 增量 |
| M3 | 是 | 否 | 是 | 形态+认知联合事件 |
| M4 | 是 | 是 | 是 | 完整联合模型 |

RQ1：M2−M1、M4−M3 检验网络增量；RQ2：比较形态、网络、认知相对事件模式，M3−M1、M4−M2 检验认知输入作用；RQ3：基于相同随访结局评价稳定性与纵向临床关联。这里的差值是比较关系，不是直接相减阶段号或跨维度似然。

独立后续认知关联是核心；样本外评分预测和 Aβ 阳性亚组是条件性扩展。既有研究已涵盖 SuStaIn、MSN、多模态联合及纵向认知验证，不能宣称首次提出这些方法。

## 2. E0 数据核验与队列构建（当前任务）

### E0.1 环境与文件盘点
- 核实当前 Git 版本、脚本、Python 依赖、审计文件及只读挂载状态；记录数据快照和处理版本。
- 查阅 V2/V3/V4 原始审计，而不是从零开始全盘扫描。优先复用已见 FS 目录；需要扩展时按候选 ID、目录和后缀分范围设独立预算。
- 检查诊断、认知合法值、访视日期、Image ID、PTID/RID 映射；对来源后缀分别处理，禁止以 Excel 同行代替同次访视。

### E0.2 实体影像和访视匹配
- 建立候选检查清单；匹配键为身份、影像检查标识和实际日期；核实 FS 处理目录的来源影像、模板与版本。
- V3 诊断 ±180 天、认知 ±90 天、Amyloid ±365 天是历史候选规则，正式规则需要核查并记录。对多扫描、重复处理、日期不明或冲突项设置可复核的处理与排除原因。
- 基线时间定义与特征可获得时间明确记录。如果认知晚于 MRI，预测或随访计时起点不能早于最后一个实际使用的基线输入；需要核实诊断时间等信息的可用性。严禁使用结局之后的信息。
- 对比 M1–M4 所需共同输入与结局覆盖，不因后续结局好坏筛选样本。

### E0.3 质量控制
- 先抽查 10–20 例覆盖 CU/MCI 的样本；确认 `aseg.stats`、`lh.aparc.stats`、`rh.aparc.stats` 可读及列定义正确；核查 eTIV、体积、厚度、面积、曲率等。
- 检查影像可读性、分割及表面重建质量、解剖标签一致性、异常/缺失值、处理版本和站点/扫描协议差异。若依赖现有 QC 字段，核实含义和适用范围。
- 抽查仅用于验证流程。正式队列必须完成所有纳入样本的规定 QC；自动筛查与必要人工复核相结合，记录每种排除原因。阈值及质控手册在正式分析前冻结。
- 如须补跑 FreeSurfer，优先对定向确定的合格 T1 补处理，保持版本一致，输出到可写受控位置；不得写入原始只读共享。先报告资源和时间估算，再启动批量任务。

### E0.4 输出与验收
本地私有产物：受试者/访视/影像索引、QC 明细、匹配及排除记录、特征可用性表、随访明细、数据版本。公开仓库只可存通过审查的汇总。
汇总至少包含：原候选数、身份匹配数、同次影像/FS 匹配数、QC 合格数、形态完整数、MSN 特征覆盖数、基线认知覆盖数、各随访终点及时间跨度、共同可比样本数、CU/MCI/痴呆分层和排除原因。网络正式构建前的 MSN 数仅为特征可用候选。
验收：匹配链可追溯，无未解决的关键身份歧义进入正式队列；全量 QC 状态明确，随访口径与时间起点确定；明确是否足以支持 M1 与后续联合比较。没有统一最低样本量；结合事件维度、参考组、亚型规模、随访覆盖和不确定性判断。若不足，先缩小特征规模或补数据并报告，禁止虚构样本量。

## 3. E1 pySuStaIn 示例与 M1

可与 E0 并行验证官方模拟示例，但真实模型训练依赖合格队列。
- 选择独立可复现环境，记录 Python/pySuStaIn 版本或 commit、依赖锁定、CPU 配置、随机种子，先运行官方模拟数据。
- 建立受试者级划分，同一人所有访视属于同一划分；记录共享划分方案，必要时交叉验证。留出测试不用于反复选参数。
- 在训练集内拟合缺失处理、协变量调整、跨个体标准化与特征筛选；优先用训练内临床 CU 定义 Z-score 参考分布。根据指标类型决定 eTIV、年龄、性别、站点等校正，不盲目统一回归。
- 筛选少量有临床依据的区域指标，记录公式、方向、事件阈值及最大 Z 值；异常增大方向统一。检查参考组规模、方差与异常值。
- 先小规模真实 M1 再扩大；多次初始化，训练内候选亚型数比较及交叉验证，记录迭代和收敛情况，不提前指定真实亚型数。
- 输出：特征字典、预处理参数、样本划分版本、拟合日志、事件序列、PVD（位置方差图）、亚型/阶段后验、不确定性及安全汇总。
- 验收：示例和 M1 运行可复现；特征与异常方向满足设置；结果可解释、无明显泄漏、模型不确定性已检查。若只能支持单亚型，应如实报告。

## 4. E2 T1-only MSN

- 统一皮层分区及节点顺序，采用同一受试者的区域多维形态向量。皮层下指标不足时保留在 M1 形态特征，不强行进入 MSN。
- 核实各节点共享同类特征、单位和定义；处理缺失与零方差。记录受试者内跨区域标准化和跨个体训练内校正的区别。
- 初步使用相关性相似度构建个体加权邻接矩阵；具体相似度、标准化、负边处理、对角线、权重到距离转换、稀疏化和网络密度规则先依据方法文献确定。不要对负权直接计算未经定义的路径指标。
- 候选全局效率、局部效率和少量节点/全局指标；核实实现对加权图、断连和距离定义的支持。
- 比较特征集、相似性度量及阈值，分析分布、冗余、异常方向及单调异常解释；明显不稳定或强非单调指标不得直接进入 Z-score 模型。CU/MCI 临床梯度只能提供辅助证据，不证明真实单调进展。
- 有重复扫描且质量合格时才能开展真实重测可靠性；没有重复扫描时只报告参数敏感性等稳定性证据。
- 验收：可复现的个体矩阵、网络指标字典、敏感性分析、筛选理由；明确可进入 SuStaIn 的指标及适用限制。若无合格指标，暂停 M2/M4 并讨论调整，而非强行拼接。

## 5. E3 M1–M4 受控建模

- 以同一可比较队列、受试者级划分、共同形态特征及预设评价方案为主要分析。M1 扩展样本模型可单列敏感性实验，不能和共同队列结果混比。
- 认知候选 MMSE、ADAS13、CDR-SB，优先 1–2 项；依据训练内覆盖、方向和冗余确定。MMSE 与 ADAS13/CDR-SB 的异常方向不同，先核查量表编码。
- 比较 M1–M2、M3–M4 的网络增量及 M1–M3、M2–M4 的认知增量；控制事件数量、尺度、特征冗余影响，必要时做特征数匹配敏感性分析。
- 各模型可有不同合适亚型数；重抽样时处理亚型标签置换，比较事件序列稳定性、亚型匹配一致性、后验和阶段不确定性。不同输入维度的原始似然和未归一化阶段不可直接判优；归一化阶段也不自动具有相同临床含义。
- 输出四组 PVD、亚型/阶段分布及后验、稳定性指标、共同队列对照表与失败记录。
- 验收：四模型共享公平比较条件且无数据泄漏；结论可追溯至真实运行，不要求 M4 必然更好。若某模型失败，记录并按风险预案处理。

## 6. E4 独立纵向认知验证与稳健性

- 在对结局进行效果检验前确定主要量表、次要量表、观察窗口、分析人群、协变量、多重比较方案和缺失/失访处理。用实际不等间隔随访时间；V3 约 12/24 月的宽容差不是正式预测标签。
- 核心：采用线性混合效应模型等，考察基线亚型×时间、阶段×时间的关联，控制年龄、性别、教育及基线认知等。随机效应结构依据重复观测和模型诊断确定。报告效应量、置信区间、样本/访视数与模型诊断，不只报告 p 值。
- M3/M4 的基线认知不能同时作为独立成功证据；后续新测量、相对变化或调整基线后的变化率是验证对象。预处理及 SuStaIn 训练不使用未来测量。
- 对照临床基线与 M1–M4，在相同人群和结局上评估额外解释价值；若采用样本外评价，冻结训练模型并在留出受试者推断亚型/阶段。区别同队列关联、内部留出验证及真正外部队列。
- 进行网络去除、认知去除、网络参数敏感性、多次初始化、交叉验证和受试者级重抽样；亚型太小或拟合不稳时如实说明。
- 输出：纵向队列流程、效应与区间、认知变化图、模型比较与稳健性结果；记录负结果和局限。
- 验收：核心纵向关联可复核，结论限定在数据支持范围；不以显著性作为阶段验收门槛。

## 7. 条件性扩展（可跳过）

E5a 认知评分预测：仅在有效随访样本充足且严格受试者级留出可行时开展。预先定义预测时点、目标与窗口，比较人口学+基线认知、区域形态、SuStaIn 硬亚型/阶段和联合模型，报告 MAE、RMSE 和校准；后验概率模型可作为追加试验，不是默认主线。
E5b Aβ 亚组：核实数据字典、0/1 编码、示踪剂、时间及 PET QC；满足纳入条件后探索。若不足不做，不等于主任务失败。
如需进展风险预测，必须先定义事件及删失，再考虑生存指标；不自动纳入核心任务。

## 8. 执行、复现与风险

| 风险 | 应对 |
|---|---|
| 真实影像交集不足 | 定向扩展或补处理；报告 QC 排除与覆盖变化 |
| MSN 不稳定或不适用 | 筛除指标、合理敏感性试验；保留 M1/M3 作为基线，核心网络路线变更需与导师确认 |
| 早期人群异常范围窄 | 有条件纳入痴呆辅助建模或敏感性分析，保持 CU/MCI 主要解释 |
| 随访不足 | 优先可支持的纵向关联，放弃预测扩展；若核心纵向验证也不可行须报告并讨论 |
| 算力或运行成本 | 先小规模计时、减少事件/候选亚型规模，合理 CPU 并行 |
| 无显著增量 | 如实报告，分析不确定性及方法假设，不反复挑选测试结果 |

每次实验记入 EXPERIMENT_LOG；设计变更需记录依据、批准状态和影响。配置与脚本可入 Git，受试者级衍生数据、分组索引、模型权重、原始输出留在本地。公开前审查协议、内容及小样本泄露风险。
